Getting started with Python and Jupyter

The codes for this book are Jupyter notebooks written in Python. There are two ways to run them: in your browser with Google Colab (nothing to install) or with a Python install on your own machine. Either is fine — start with Colab if you just want to run a notebook today.

Option A — Google Colab (no install)

Google Colab runs Jupyter notebooks in your browser for free; you only need a Google account. Every chapter page carries an Open in Colab link beside each notebook — one click opens it, with nothing to download, upload, or install. Run a cell with Shift+Enter; run the notebook top to bottom the first time, since later cells use results from earlier ones.

Both versions work in Colab. The _thermo notebooks need the thermo package and the property data, which a Colab session does not have — so each one starts with a short setup cell that fetches them from the code repository. Just run it first. (The same cell does nothing when you are working from a local clone, so it is not something to delete.) The libraries themselves — NumPy, SciPy, pandas, Matplotlib — are already installed in Colab.

Colab does not save your edits back to the repository. If you change a notebook and want to keep the changes, use File → Save a copy in Drive first — otherwise your work is lost when the session ends. This is the one real drawback of Option A, and a reason to move to Option B once you are working on problem sets rather than reading.

Option B — Install Python and Jupyter locally

Use uv. It is a single tool that installs Python itself, creates the project’s virtual environment, and installs the libraries — the job that used to take Anaconda plus pip plus a few conventions you had to learn first. It is also fast enough that rebuilding an environment is not something you avoid.

  1. Install uv (once, then forget about it):
    curl -LsSf https://astral.sh/uv/install.sh | sh — macOS/Linux
    powershell -c "irm https://astral.sh/uv/install.ps1 | iex" — Windows
  2. Get the code. Clone the code repository so you have the notebooks, the thermo package, and the reference data together:
    git clone https://github.com/emfurst/cbet6e.git
  3. Launch: cd cbet6e/code then uv run jupyter lab. The first run creates the environment from pyproject.toml and installs everything; later runs start straight up. Open a chapter notebook and run cells with Shift+Enter.

You never “activate” anything: uv run <command> uses the project’s environment automatically, and uv add <package> adds a library to it. If you would rather use the older route, python3 -m venv .venv followed by pip install numpy scipy pandas matplotlib jupyterlab openpyxl gives the same result — the notebooks do not care which tool built the environment.

Optional but recommended: work in an editor with an AI coding assistant (VS Code with Claude Code or Copilot, or Cursor) that can run cells and help debug. The chapter notation files that make the assistant follow the book’s conventions ship with the repository, in code/grounding/ — see How to use AI with this book.

Which should I use?

Colab is best for zero setup, a Chromebook, or trying one notebook. A local install is better for working offline, faster runs, and the everyday engineering workflow you will keep using after this course.

More depth (shell, version control, environments) is in the computing-setup and cli-walkthrough guides.
